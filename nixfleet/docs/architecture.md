# nixfleet — Architecture

nixfleet is an integrated homelab control plane for this NixOS flake repository.
It is **not** a general dashboard and **not** a NixOS replacement: it is a UI +
API + agent layer on top of the existing declarative model (NixOS, deploy-rs,
`nh`, microvm.nix). It never bypasses the declarative workflow.

This document is the design artifact produced before any implementation
(repository analysis → integration points → structure → data flow → API →
plugin system → agent protocol → roadmap).

---

## 0. Binding design decision: "Nix First"

> **Alles, was sinnvoll deklarativ modelliert werden kann, gehört zuerst nach
> Nix. Alles, was echte Runtime ist, gehört nach Go.**

Nix is the single source of truth. Go is runtime. React is presentation.

### Decision procedure — applies to every new feature

Before implementing anything, in this order:

1. **Can this information be described declaratively?**
2. **Can it be derived from the existing data model** (roles, bundles,
   presets, hosts, modules, package registry, module flags)?
3. **Can it be generated during flake evaluation?**

If the answer is **yes**, the logic goes into Nix, **not** Go:
data model extension → generated artifact (JSON) → Go reads it → React renders it.

If the answer is **no** (genuine runtime: network I/O, auth, streaming, DB,
process control), it goes into Go as before.

### What belongs where

| Layer | Contents |
|---|---|
| **Nix** | navigation, pages, menus, dashboard layout, widgets, host metadata, roles, bundles, presets, feature flags, UI configuration, plugin selection/registry metadata, reverse-proxy routes, permission policy, defaults, everything derivable from the flake |
| **Go** | HTTP/REST, WebSockets, SSH, terminal, reverse proxy, SQLite, sessions, streaming, systemd/podman/tailscale communication, deploy-rs/nixos-rebuild invocation, journald, live metrics — all runtime only |
| **React** | pure presentation. Renders structures generated by Nix; does not decide what exists, what is visible, or how it is configured |

Go and React must **not** invent structure: any page, nav item, widget,
plugin or permission that exists in the UI has its declarative origin in Nix.

## 1. Repository analysis (what exists, what we reuse)

| Layer | Existing structure | nixfleet usage |
|---|---|---|
| Framework | in-repo `lib/framework` (`applyHost`/`applyHome`), `specialArgs.frameworkLib` | read-only: host configs already evaluated |
| Data model | `data/roles/`, `data/bundles/`, `data/presets/`, `data/packages/{system,home}.nix`, `data/hosts/<host>/` | read-only, exposed via manifest (below) — never duplicated |

| Deploy | `deploy-rs` (`flake.deploy.nodes.{x270,mireo}`, `activateNixosWithNixPath`), apps `rebuild` (`nh os switch`), `deploy-x270`/`deploy-mireo` (deploy-rs) | invoked **as-is** by the deploy plugin — never reimplemented |
| MicroVMs | `microvm.nixosModules.host`, 7 VMs via `mk-microvm` (autostart, `microvm@<name>` units, MAC from IP, tap→br0) | VM list from manifest; lifecycle via systemd units + serial console |
| Secrets | sops-nix (x270), `lucy.secrets`, `.sops.yaml`; `mkKeyGenService` for runtime secrets | agent tokens via sops; runtime secrets via keygen pattern |
| Topology | pure-Nix SVG fixer pattern (`nix eval --impure` + `SVG_PATH`, CI commits results) | same pattern for the **artifact generators** (`nixfleet-manifest`) |
| Checks/CI | `tests/default.nix` (dotfiles-tests, topology-unit, builders-unit), `frameworkChecks`, `deployChecks`, ci.yml (check-light/check-full/eval/topology) | nixfleet package joins `dotfiles-tests` deps; new CI jobs for Go/frontend/artifacts |
| Scripts | `lib/*.nix` `writeShellApplication` builders, apps in flake | nixfleet binaries as flake packages + systemd services |

Deliberately **not** reused as code: nothing — nixfleet adds new code only where
no existing mechanism exists (UI, API, agent protocol). All system actions go
through existing tools (`systemctl`, `journalctl`, `nix`, `nh`, `deploy-rs`,
`podman`, `ip`, `smartctl`), invoked by agent plugins. The rule "no shell
hacks" applies to the **agent/API protocol** (structured JSON), not to plugin
internals, which are thin, deterministic wrappers around the host's own tooling.

## 2. Deployment topology

```
Browser ──HTTPS──▶ nixfleet API + SPA  (mireo host, :8443)
                      │
                      │ WebSocket (JSON protocol, agents connect OUTBOUND)
                      ├── agent: mireo      (host itself)
                      ├── agent: x270       (laptop, connects via LAN/tailnet)
                      └── agent: 7 microvms (grafana, network-services, monerod,
                                             yammat, cups, sshkeys, aptcache)
```

- **API + web run on mireo** (always-on server, has all VMs). Port 8443, TLS
  with a locally generated CA (mkKeyGenService-style); ACME/tailnet-cert later.
- **Agents connect outbound** — no inbound ports needed on managed hosts; works
  behind NAT (mireo is the router, VMs are behind br0).
- Agent endpoint per host is generated by Nix (`lucy.nixfleet.agent.endpoint`);
  x270 uses `https://nixfleet.lan:8443` / tailnet IP when away.
- microvm agents: a tiny agent config is appended to `microvm-base.nix` (one
  `imports = [ ... ]` + `lucy.nixfleet.agent.enable = true`), so all 7 VMs get
  it for free with zero per-VM duplication.

```text

    auth/                 # sessions, CSRF, audit; RBAC/2FA/WebAuthn interfaces
    store/                # SQLite (jobs, audit, sessions, build history)
    proxy/                # /apps/<name> reverse proxy (routes from artifact)
  cli/                    # Go binary: `nixfleet` CLI client (deploy, status, gc)
  shared/                 # JSON models, protocol types (imported by all)
    proto/                # ws envelope, request/response types
    models/               # API models (host, unit, journal entry, vm, ...)
    openapi.yaml          # OpenAPI 3 source (oapi-codegen input)
  web/
    frontend/             # React + TS + Tailwind + xterm.js + Chart.js (Vite)
      src/features/       # presentational feature components (see §11)
    backend/              # Go package serving the built SPA + auth cookie paths
  docs/                   # this doc + plugin API + deployment + dev guide
  tests/                  # Go integration tests (fake plugins), API tests
  artifacts/              # generated files, committed (CI), like docs/topology/
    manifest.json         # hosts, data model, VMs, proxy routes, feature flags
    ui.json               # navigation, pages, menus, dashboard/widget layout
  manifest.nix            # pure-Nix artifact generators (flake app inputs)
```

## 4. Generated artifacts (no double configuration, no invented structure)

Everything static is **derived from the flake during evaluation**, written as
JSON, committed by CI, and only *read* by Go and React. Nothing is configured
twice.

`nixfleet/manifest.nix` — pure Nix `{ flake }: { manifest, ui }`:

- **manifest.json** (host facts):
  - hosts: name, roles (from `data/hosts/<host>/roles.nix`), bundles, presets,
    moduleFlags, package tags, module list, topology annotations
  - VMs: name, ip, mem, vcpu, ports, volumes (from `microvm.vms`)
  - deploy nodes (deploy-rs), proxy routes (`lucy.nixfleet.proxy.*`),
    agent plugin selection per host (`lucy.nixfleet.agent.plugins`),
    feature flags per host (derived from moduleFlags + enabled plugins),
    available plugins/API surface per host
- **ui.json** (UI structure — entirely declarative):
  - navigation tree, pages, menus (`lucy.nixfleet.ui.*`, see §10)
  - dashboard layout: widget list per host (widget type, data source,
    chart config, refresh interval)
  - enabled features per host → visibility of pages/sections
  - permission policy skeleton (see §12)

Generation pipeline: flake app `nixfleet-manifest` runs `nix eval --impure`
(pure Nix → stdout, same pattern as `fix-network-svg`); CI job regenerates
and commits `nixfleet/artifacts/*.json` (like the topology job commits SVGs).

Go loads both files at start; React receives them via `/api/v1/meta`
(API forwards the artifacts verbatim). If it is not in an artifact, it does
not exist in the UI.

## 5. Data flow

```
Nix evaluation ──▶ artifacts (manifest.json, ui.json) ──▶ committed by CI
                                                            │
Browser SPA ◀── /api/v1/meta (artifacts verbatim) ◀─────────┤
  │  HTTPS  /api/v1/* (REST, JSON)       │  WSS /api/v1/ws (events, streams)
  ▼                                     ▼
API  ──▶ auth (session/CSRF/audit/RBAC-policy from Nix) ──▶ ws hub
  │                                                        │
  │ API-side plugins (runtime only)                        │ agent protocol (JSON)
  │  git, github, deploy                                   ▼
  ▼                                                        AGENT (per host)
runner (mireo): nix/nh/deploy-rs                    plugins: systemd journal nixos
  │  existing tools, streamed logs                        microvm podman network
  └─▶ deploy jobs in SQLite                                files terminal metrics
                                                           smart tailscale
```

- Structure flows **Nix → artifacts → Go → React** (one direction).
- Runtime flows Go ↔ agent over WS, Go ↔ host tools.
- REST for commands/queries; WS for everything streaming (journal, deploy
  logs, terminal, VM console, metric feed).
- One WS connection per agent (multiplexed by stream id); browser gets one WS
  per page with subscription topics (`journal:<host>`, `unit:<host>:<unit>`,
  `deploy:<id>`, `console:<vm>`).

## 6. Agent protocol (JSON over WebSocket)

Envelope (shared package `nixfleet/shared/proto`):

```jsonc
{ "id": 42,                    // request id (client-generated)
  "type": "request",           // request | response | error | event
  "stream": "journal:mireo",   // stream id for multiplexing; "" for one-shot
  "plugin": "systemd",
  "method": "restart",
  "params": { "unit": "microvm@cups" },
  "result": { "ok": true }     // response
  "error": { "code": "NOT_FOUND", "message": "..." }  // error
  "event": { "ts": 0, "chunk": "..." } // event: streamed data chunk
}
```

- One-shot request/response with `id` correlation; long streams are
  request+`stream` then `event` frames until an end-event.
- Auth: agents present `Authorization: Bearer <agent-token>` on connect;
  API validates against sops-decrypted token map (`nixfleet/agent-tokens.yaml`).
- Reconnect: exponential backoff (1s…60s) + jitter; agent re-reports state on
  connect (capability list, host info, generation).
- Timeouts: requests carry `ttl_ms`; API cancels on agent disconnect.
- No shell strings cross the wire: every action is `plugin + method + params`.

## 7. Plugin system

**Selection and metadata are Nix; execution is Go.** The catalog of which
plugins exist, which hosts have which plugins enabled, and which API surface
that implies lives in the artifacts (from `lucy.nixfleet.agent.plugins` +
module flags). Go compiles all capabilities statically but **serves only what
the artifact declares**; the UI renders only what the artifact lists.

Go capability interfaces (agent side and API side are separate registries):

```go
type AgentPlugin interface {
    Name() string
    Init(ctx context.Context, env *Env) error   // env: agent config, logger, store
}

// capabilities — a plugin implements any subset:
type CapSystemD interface { ListUnits(ctx, Filter) ([]Unit, error); Restart(...); ... }
type CapJournal  interface { Stream(ctx, Filter, cb func(Entry)) error }
type CapNixOS    interface { Generations(ctx) ([]Generation, error); Rollback(ctx) error; GC(ctx, dry bool) (GCReport, error); Build(ctx, target, cb) error }
type CapMicroVM  interface { ListVMs(ctx) ([]VM, error); Lifecycle(ctx, name, Action) error; Console(ctx, name, cb) error; Logs(ctx, name, cb) error }
type CapContainers interface { List(ctx) ([]Container, error); Logs(ctx, id, cb) error; Restart(ctx, id) error; Exec(ctx, id, cb) error; Images/Volumes(ctx) }
type CapNetwork  interface { Interfaces(ctx) ([]Iface, error); Routes/Ports/Firewall(ctx) }
type CapFiles    interface { List/Read/Write/Upload/Download/Zip/Chmod(ctx, Path) }
type CapTerminal interface { Open(ctx, spec TerminalSpec, cb func(Output)) (SessionID, error); Resize(ctx, id, rows, cols); Close(ctx, id) }
type CapMetrics  interface { Snapshot(ctx) (Metrics, error) }   // agent polls every 5s
type CapTailscale interface { Status/Peers(ctx) }               // optional plugin
```

Registry: plugins register capabilities at compile time (no dynamic loading);
the artifact decides enablement per host. The API dispatches by
`plugin + method` — an unknown plugin/method is a protocol error (never shell).

Plugin ↔ host tooling mapping (existing mechanisms, never replaced):

| Plugin | Tooling | Notes |
|---|---|---|
| systemd | `systemctl`, unit files | list/status/start/stop/restart/reload/enable/disable |
| journal | `journalctl -o json[-f]` | filter: unit, priority, since, match |
| nixos | `nix-env -p /nix/var/nix/profiles/system`, `switch-to-configuration`, `nix store gc`, `nix build` | generations (booted/current), rollback, gc dry-run+collect, flake check/eval/test/topology (eval GUI) |
| microvm | `systemctl [start|stop|restart] microvm@<name>`, qemu serial socket | console via serial socket; snapshots: prepare (stop + overlay copy) — deferred |
| podman | `podman ps -a --format json`, logs, restart, exec, images, volumes | repo uses podman (iVentoy); not docker |
| network | `ip -j [addr|route|link]`, `ip -j rules`, `ss -tulpn`, `nft list ruleset` | iproute2 JSON output |
| files | Go `os` + `archive/zip` | path allowlist from config (`lucy.nixfleet.agent.files.roots`) |
| terminal | `creack/pty`, local `ssh -t <user>@localhost` | user from config (default `lucy`); multiple sessions, resize, copy/paste, UTF-8 |
| metrics | `/proc`, `sysfs` thermal, `smartctl -j -a` (optional) | CPU/RAM/swap/load/net/disk/SMART/temps/processes |
| tailscale | `tailscale status -json`, `--peers` | optional, enabled only if `tailscale.enable` |

API-side plugins (run on the API host):

| Plugin | Tooling | Notes |
|---|---|---|
| deploy | `nix build --dry-run` + `nvd diff`, `nh os switch` / `deploy-rs` per host | orchestrates the workflow §8; logs streamed to browser |
| git | git CLI on the repo checkout (`lucy.nixfleet.git.repo`) | status/diff/history; optional commit+push |
| github | `gh`/REST with PAT from sops (`lucy.nixfleet.github.token`) | actions runs, releases |

## 8. Deploy workflow (existing mechanisms only)

Per host, API-side deploy plugin runs the exact same commands the user would
run, with a pre-flight diff step:

```
1. evaluate   nix flake check (host runner)
2. build      nix build .#nixosConfigurations.<host>.config.system.build.toplevel
              + nvd diff /run/current-system $result        → package changes
              + unit diff (compare systemd unit lists)      → restarted services
              + generation number preview                    → new generation
3. show diff  UI: affected hosts, changed packages, restarted services, modules
4. confirm    explicit user confirmation (audit-logged)
5. deploy     nh os switch (rebuild) | deploy-rs (deploy-x270 → localhost, deploy-mireo → 10.8.0.1)
6. live logs  WS stream of build/activation output
7. result     success/failure → jobs table in SQLite; agent reports new generation
```

Rollback: list generations (`nix-env`), trigger `switch-to-configuration --rollback`
on the target (via its agent), stream live status. GC: dry-run sizes →
confirm → `nix store gc`/`nix-collect-garbage -d`, show freed space.

## 9. API design

- **REST** `/api/v1`, OpenAPI 3 source in `nixfleet/shared/openapi.yaml`,
  Go code generated with `oapi-codegen` (typed models, no unchecked JSON maps).
  API *metadata* (route visibility, host/feature availability) comes from the
  artifacts wherever practical; OpenAPI itself stays in Go (it describes
  runtime endpoints, not structure).
- Endpoint groups (design):
  - `auth`: login, logout, session info, password change (2FA/WebAuthn stubs)
  - `meta`: artifacts verbatim (manifest.json, ui.json) — the UI bootstrap
  - `hosts`: list (merged artifact + agent state), detail, connect events
  - `hosts/{h}/units`, `/journal`, `/metrics`, `/processes`, `/files`, `/network`, `/terminal`
  - `vms` (list/lifecycle/console/logs), `containers` (list/logs/lifecycle/exec)
  - `deploy`: candidates (dry-run diff), confirm, jobs, logs, rollback
  - `nixos`: generations, gc, eval/check results
  - `git`: status/diff/history; `github`: runs/releases
  - `apps/*` (proxy), `system`: health, version
- **M1 as implemented (direct, no OpenAPI yet)**: `GET /api/v1/hosts`, `GET /hosts/:host/health` (`healthy|degraded|critical|unknown`, `failedUnits`), `/:host/resources` (`/proc`), `/:host/network` (`ip -j`), `/:host/vms` (merged `configured` from manifest + `runtime` via `systemctl is-active microvm@<name>` validated), `/:host/systemd/failed` (`systemctl --failed`) — typed Go structs, `404` for unknown host/vm, `503` when agent not local, no shell strings.
- **WebSocket** `/api/v1/ws` — same auth; topics `journal:<h>`, `deploy:<id>`,
  `console:<vm>`, `metrics:<h>`, `unit:<h>:<u>`; browser multiplexes.
- **Auth**: single admin (`lucy`) initially. Argon2id password hash, bootstrap
  via `nixfleet setup` on the API host. Sessions: 32-byte random token, SQLite,
  expiry + sliding refresh. Cookie `nixfleet_session` (HttpOnly, SameSite=Lax,
  Secure) + `X-CSRF-Token` header; CLI uses `Authorization: Bearer`.
- **Prepared interfaces** (defined, not implemented): `TOTPProvider` (2FA),
  `WebAuthnProvider` (passkeys), `RBAC`. The permission *policy* is declared
  in Nix (`lucy.nixfleet.rbac.*`, emitted into the artifact); Go enforces it
  through one `authorize(ctx, action, resource)` hook. First implementation =
  single admin with full grants.
- **Audit log**: every action (login, deploy, restart, rollback, gc, file
  write, terminal open) → `audit` table: actor, action, resource, result, ts,
  remote IP, request id.
- **SQLite** `/var/lib/nixfleet/nixfleet.db`: `sessions`, `audit`, `jobs`
  (deploy/action history + status + log tail), `builds` (eval/check/build
  history). WAL mode; migrations embedded (startup).
- **Reverse proxy** `/apps/<name>`: routes declared in Nix
  (`lucy.nixfleet.proxy.grafana.target = "http://10.8.0.2:3000"`) and carried
  in manifest.json; Go enforces auth (nixfleet session) before proxying;
  sub-path apps (grafana) get `serve_from_sub_path` noted in docs. No plain
  passthrough.

## 10. Nix integration (new module + apps)

- `modules/nixos/nixfleet.nix` — `lucy.nixfleet.*` (M1: `role` still used for `apiHost` in `manifest.nix`, but **services are now package-gated, not role-gated** — any host with `enable` + `api.package` runs `nixfleet-api`, any with `enable` + `agent.package` runs `nixfleet-agent`, so `mireo` as `role = "api"` also runs the agent):
  - `enable`, `role` = `api` | `agent` | `cli`
  - `api`: port 8443 (mireo firewall `br0` allows 8443), `artifactsDir` (mireo: `../../../nixfleet/artifacts`), `webDir` (via `flake.nix` `nixfleetPkgs.web` when built, currently `null` to avoid `deepSeq` stack overflow), TLS cert/key paths (generated by keygen service), `proxy.<name>.target`, sops file `nixfleet/agent-tokens.yaml`
  - `agent`: `endpoint`, `tokenFile` (sops-decrypted, mode 0600), `plugins` (mireo: `["systemd" "journal" "metrics"]`), `files.roots`, `terminal.user`
  - `ui` (declarative UI structure → ui.json):
    - `navigation` (tree of pages/sections, M1: `hasVms` now correctly via `attrNames vmCatalog` so `/vms` appears)
    - `dashboard.<host>?` / `dashboard.widgets` (widget type, data source, chart config, refresh interval)
    - `pages` (feature toggles, e.g. tailscale page only where plugin enabled)
    - `menus`, `featureFlags`
  - `rbac` (permission policy: role → allowed actions per resource)
  - Registered like every other module; host selection stays in `data/` (mireo: `data/hosts/mireo/settings.nix` `enable = true; role = "api"`; `x270` not enabled; `flake.nix` provides `nixfleetPkgs.*` defaults)
  - `nixfleet/manifest.nix` fixes (M1): `hasVms` via `attrNames`, `hostRoles` via `hasAttr "roles.nix"` (was `? roles.nix` invalid) — `x270` now correctly exposes roles/bundles/presets.
- Flake apps: `nixfleet` (CLI), `nixfleet-manifest` (artifact generators).
- Flake packages: `nixfleet-agent`, `nixfleet-api`, `nixfleet-cli` (Go,
  `buildGoModule`), `nixfleet-web` (Vite build, embedded in api binary).
- The three binaries join `dotfiles-tests` dep list (built in CI);
  agents/services activate via the existing deploy flows.

## 11. Frontend

- React 18 + TypeScript + Vite, TailwindCSS, react-router, dark mode default
  (Stylix-neutral), responsive.
- **Pure presentation**: the app boots from `/api/v1/meta` (ui.json +
  manifest.json) — navigation, pages, menus, dashboard widgets, enabled
  features are data, not code. Feature components register renderers keyed
  by widget/page type; the *presence and configuration* comes from Nix.
- Charts: Chart.js (widget config from Nix). Terminal: xterm.js + addons
  (fit, web-links).
- `src/features/<feature>/{components,hooks,api}.ts` holds presentational
  components only (journal viewer, unit table, terminal pane, ...); no
  business logic, no hardcoded host lists, no invented pages.
- Live updates via one WS hook (`useStream(topic)`), auto-reconnect.

## 12. Security model

- TLS on API (generated CA; clients pin it via Nix-provided CA bundle);
  agent tokens per host (sops), never in the store; files plugin path-
  allowlisted; terminal restricted to configured user; audit everything;
  CSRF on state-changing requests; no secrets in logs/frontend.
- RBAC policy declared in Nix, enforced in Go, surface derived from the
  artifact (a page without permission is not rendered and not reachable).
